# Изменения

## 1.0.9 — 2026-11-19

### НАСТОЯЩАЯ причина пустой канвы

Журнал кадров (добавлен в 1.0.8) показал: `кадр №1: 2 мс … надписей 0 из 571` — то есть рендер
отрабатывал мгновенно и **ничего не рисовал**. Причина не в GDI и не в скорости:

1. Буфер проекции (`points_cap`) создавался один раз под **демонстрационный** чертёж (десятки точек).
   Для настоящего файла (5394 точки) `frame()` возвращал `Overflow` и **не рисовал ничего**.
2. Ошибка кадра в окне **молча глоталась**: `let _ = renderer.frame(...)`. Поэтому ни сообщения, ни
   следа в журнале — просто пустая канва.

Исправлено:

- буфер проекции выделяется под фактический чертёж при каждой загрузке (+1024 точки запаса);
- ошибка кадра больше не глотается: пишется в журнал, увеличивает буфер и повторяет отрисовку,
  а если не вышло — текст ошибки виден в статусной строке;
- **демонстрационный чертёж удалён** (по просьбе владельца): без файла открывается пустое окно
  с подсказкой «ФАЙЛ НЕ ОТКРЫТ · Ctrl+O или перетащите .dxf» вместо выдуманной геометрии;
- надписи рисуются **порциями** (64 → 128 → 256 … за кадр) и растут только если кадр лёгкий;
- аварийный режим без GDI-текста: если кадр дольше 2 с — текст отключается (засечки вместо букв),
  `F9` возвращает; событие пишется в журнал;
- в журнал добавлен замер **по фазам**: геометрия отдельно, текст отдельно, и сколько надписей
  отрисовано из общего числа.

Проверка живого окна (не `--selftest`): `кадр №1: 7 мс (геометрия 1, текст 6) · надписей 315 из 571`
— то есть кадр действительно рисуется, 256 надписей за кадр, остальные засечками.

64 теста зелёные.

## 1.0.8 — 2026-11-19

### Отрисовка надписей: кадр больше не встаёт на старых машинах

Журнал с Win7 показал главное: чертёж **загружался** (`чертёж установлен: объектов 1958, отрезков 918,
надписей 571`), а зависала **отрисовка первого кадра**. Причина — работа на каждую надпись:

| Что было | Что стало |
|---|---|
| маска чистилась целиком: 1024 × 40 = 40 960 пикселей **на каждую** надпись (571 надпись → 23 млн записей в кадре) | чистится только прямоугольник строки: ширина × высота |
| копирование вслепую `0..512` колонок | копируется измеренная ширина строки |
| `measure()` вызывался на каждую надпись в цикле + внутри рисования | ширина для рамки считается арифметикой; GDI — один раз |
| `CLEARTYPE_QUALITY` (сглаживание, дороже) | `NONANTIALIASED_QUALITY` — жёсткие края и по стилю, и втрое быстрее |
| каждая надпись каждый кадр заново шла в GDI | **кеш глифов**: повторные строки («Изм.», «Лист», «Подп. и дата») берутся из памяти, до 8 МБ |
| надписи за пределами канвы тоже измерялись и рисовались | отсекаются до любых вычислений |
| бюджет надписей фиксированный 1200 | **адаптивный**: кадр > 40 мс → бюджет делится, < 14 мс → растёт (до 1200) |

### Журнал теперь показывает отрисовку

`%LOCALAPPDATA%\dxfsign\startup.log` пишет время первого кадра каждого чертежа и любой кадр
медленнее 500 мс:

```
старт: Windows 6.1 build 7601 | cwd "C:\Users\…\Downloads" | аргументы []
окно создано: 1440x900
открываю: …\КЭВ-39П3112(3)W.dxf
чертёж установлен: объектов 1958, отрезков 918, надписей 571, слоёв 7
кадр №1: 4 мс (надписей 571, бюджет 1200, объектов 1958)
```

По этим строкам видно, где именно встало: чтение, разбор, установка или отрисовка.

Замер на этом файле: **0.9 мс на кадр** при 571 нарисованной надписи (было — десятки миллисекунд
работы на каждую надпись на бумаге старого CPU). 64 теста зелёные.

## 1.0.7 — 2026-11-19

### Одна сборка, и она работает на Windows 7

Главная причина «на Win7 вообще не грузит»: **основной exe** собирался текущим rustc и импортировал
`api-ms-win-core-synch-l1-2-0.dll` — на Windows 7 такого файла нет, процесс умирал до появления окна.

- Теперь **единственный** `dxfsign.exe` собирается rustc **1.77.2**, и в его импортах **ноль**
  Win8+ функций (проверяется `objdump`: `api-ms-win-core-synch`, `WaitOnAddress`,
  `GetSystemTimePreciseAsFileTime`, `SetThreadDescription` — 0 совпадений).
- Остаётся требование Windows 7 **SP1 + KB2999226** (Universal C Runtime) — без него не запустится ни
  одна современная программа, включая эту. Список DLL: `KERNEL32, USER32, GDI32, comdlg32, SHELL32,
  ole32, ADVAPI32, bcrypt, ntdll, api-ms-win-crt-*`.

### Окно больше не уезжает за экран

Окно создавалось жёстко 1440×900. На Win7-ноутбуке (1366×768 и меньше) оно выходило за пределы экрана —
это и выглядело как «не грузит»: видно было пустоту или часть панели.

- Размер окна теперь берётся из **рабочей области** (`SystemParametersInfo(SPI_GETWORKAREA)`) с полями.
- Панели **адаптивные**: на узком окне левая 22%, правая 24% (минимум 190/200 px), на широком —
  прежние 340/400. Канва на 1024 px стала 56% ширины вместо 43%.

### Надписи читаются: клик по списку приближает к надписи

Тот DXF из «Загрузок» (`КЭВ-39П3112(3)W.dxf`, 1.5 МБ) разбирается за **0.01 с** (1958 объектов,
571 надпись) — но вписанный в узкую канву лист выглядел полосой, где текст не разобрать.
Теперь **клик по надписи в левом списке центрирует и увеличивает** вид до читаемых 22 px по высоте
надписи; если надпись уже крупная — масштаб не меняется, только сдвиг. `F7` — вписать весь чертёж.

### Диагностика для «на другом компьютере не грузит»

- `%LOCALAPPDATA%\dxfsign\startup.log` — журнал: версия, версия Windows, каталог запуска, аргументы,
  «окно создано: WxH», «открываю: путь», «чертёж установлен: объектов N, отрезков N, надписей N»,
  причина отказа загрузки.
- Перехват падений: паника пишется в журнал и показывается окном с текстом — приложение больше не
  исчезает молча.
- `DXFSIGN_SCALAR=1` — принудительно скалярная проекция (без AVX2): если так работает, а без флага нет,
  виноват SIMD-путь.
- `dxfsign.exe probe <файл>` печатает процент и скорость чтения.

## 1.0.6 — 2026-11-19

### «Висит на чтении 66%, 0 объектов»

Чтение файла шло в том же потоке, что и весь загрузчик: `read` на «залипшем» файле
блокируется навсегда, поэтому ни отмениться, ни сообщить о проблеме было нельзя — окно просто
показывало «чтение 66%».

- Чтение вынесено в **свой поток** и отдаёт куски через канал; загрузчик ждёт их с таймаутом.
  **Esc отменяет мгновенно** (проверка раз в 200 мс), даже если `read` всё ещё висит.
- Если данных нет **15 секунд**, загрузка прекращается с объяснением и перечнем реальных причин
  (антивирус проверяет файл; файл — облачная заготовка; диск занят или отключился; отвалился
  сетевой диск) — без голого «зависло».
- **Облачные заготовки** (OneDrive, Яндекс.Диск и подобное) распознаются по атрибутам
  `FILE_ATTRIBUTE_RECALL_ON_OPEN/DATA_ACCESS/OFFLINE`: экран загрузки прямо говорит, что первое
  чтение ждёт скачивания, а не «думает».
- На экране загрузки теперь видно **сколько прошло** и **скорость с оценкой остатка** — «медленно»
  и «встало» больше не выглядят одинаково.

### Диагностика: `dxfsign.exe probe <файл>`

Читает файл и печатает прогресс со скоростью. Если чтение встанет, в консоли будет видно, на каком
проценте и сколько секунд нет данных:

```
файл:  \\srv\project\щит.dxf
размер: 84.3 МБ
  чтение: 41% (34.6 МБ, 22.1 МБ/с)
  чтение: 66% — данных нет 6 с (считается зависанием через 15 с)
```

64 теста зелёные (добавлены: чтение целиком, отмена до чтения, отсутствующий файл, пустой файл,
распознавание облачной заготовки).

## 1.0.5 — 2026-11-19

### Сохранение: занятый файл определяется ДО ротации версии

Симптом владельца: «версию сохраняет с таймстампом, но ничего не правит» и «отказано в доступе»
в папке с полными правами. Причина — файл был открыт в AutoCAD:

- проверка прав, атрибута «только чтение» и **занятости файла** теперь идёт **первым шагом**, до
  чтения прежней версии и до её записи в `_VERSIONS`;
- сообщение говорит причину и действие: `файл открыт в другой программе (обычно AutoCAD). Закройте
  чертёж в AutoCAD и повторите — тогда создадутся и версия, и письмо`;
- пока файл занят, версия **не создаётся** (раньше таймстамп появлялся, а чертёж оставался прежним);
- запись стала устойчивой к SMB: повтор переименования с нарастающей паузой, снятие атрибута
  «только чтение», а если шара не умеет переименовывать поверх — запись на месте с проверкой
  контрольной суммы.

### Спул: папка появляется и её можно задать

- `spool_dir` по умолчанию относительный (`_SPOOL`) — он считался от **текущего каталога процесса**,
  то есть у ярлыка мог попасть в `C:\Windows\System32` (отсюда «отказано в доступе») и не появлялся
  рядом с чертежом. Теперь относительный путь считается **от папки чертежа**.
- Каталог спула создаётся заранее, до записи письма; если создать нельзя — сообщение называет путь.
- **F5 в окне** — выбор папки спула системным диалогом, путь пишется в ini и показывается в панели.

### Правка

- **Комментарий без номера провода**: режим «комментарий» (`F3`) больше не требует номера —
  замечание идёт в перечень изменений и в письмо, текст надписи не меняется.
  В консоли: `dxfsign.exe edit файл.dxf --idx 1 --comment "замечание"` (без `--wire`).
- **Свободный возврат кликом**: на шаге «номер провода» клик по полю **ТЕКСТ** возвращает к правке
  текста, а не просто ставит курсор.

### Разбор: убран второй проход и обрыв на битой строке

- Разбор **больше не прекращается** на первой непонятной строке кода — из-за этого прогресс замирал
  на середине файла (наблюдалось «53%»), а чертёж приходил пустым. Битые строки считаются в
  `bad_lines` и видны в `report`.
- Вставки блоков собираются в главном проходе и разворачиваются **после** него: файл больше не
  читается второй раз, поэтому этап «разбор» идёт до конца и прогресс не замирает.
- Индекс блоков — хеш-таблица вместо перебора всех блоков на каждую вставку; карта слоёв строится
  один раз на блок, а не на каждую сущность.
- Потолок развёрнутых объектов: не больше 4 000 000, лишние вставки считаются в `truncated_inserts`
  вместо ухода в своп.

| Замер | 1.0.4 | 1.0.5 |
|---|---|---|
| `hard.dxf` — 820 000 объектов (300 слоёв, 400 блоков, 20 000 вставок) | 1.1 с | **0.10 с** |
| `autocad_like.dxf` — 2000 блоков, 40 000 вставок | 0.6 с | **0.12 с** |
| кадр на 150 000 отрезков | 20 мс | 16 мс |

59 тестов зелёные.

## 1.0.4 — 2026-11-19

### Больше не «не грузит»: загрузка в фоне

- Чтение и разбор идут в **отдельном потоке**, окно появляется сразу и продолжает
  перерисовываться. Экран загрузки показывает этап («чтение файла» / «разбор чертежа»), процент
  и число разобранных объектов; **Esc отменяет** загрузку.
- Файл из аргумента командной строки тоже грузится после появления окна, а не до него.
- Проверка отмены — раз в 8192 тега (отклик мгновенный, накладных расходов нет).
- Открытие файла `hard.dxf` (2.7 МБ, 300 слоёв, 400 блоков, 20 000 вставок → 820 000 объектов):
  окно на экране через **0.3 с**, полная загрузка 2.8 с, кадр не блокируется.
- Потолки названы явно: файл больше **1.5 ГБ** и больше **4 000 000** объектов не разворачиваются —
  вместо зависания выводится сообщение, что делать.

### Сохранение: «отказано в доступе (os error 5)» объясняется словами

Причина была в том, что протокол начинал писать до проверки прав, и человек видел голый код.

- Перед записью проверяются **права на каталог** (пробный файл) и **атрибут «только чтение»** у файла.
- Сообщение теперь говорит, что именно случилось и что делать:
  - `«папка» — отказано в доступе (нет прав на папку или файл помечен «только чтение»)`;
  - `файл помечен «только чтение»: снимите атрибут или сохраните через «Сохранить как»`;
  - `файл занят другой программой (закройте его в AutoCAD и повторите)` (os error 32);
  - `путь не найден (проверьте, что сетевой диск подключён)` (os error 2).
- Если прав нет, кнопка «СОХРАНИТЬ» больше не теряет работу: файл, перечень и письмо пишутся
  в резервное место `%LOCALAPPDATA%\dxfsign\outbox`, путь показывается в строке состояния.
  В консоли то же самое делает `save --fallback`.
- Если каталог версий недоступен, цепочка версий ведётся в локальном кэше, чтобы протокол дошёл до
  проверки прав, а не падал на первом шаге.

### Быстрее на реальных чертежах

- Поиск слоя по имени — **хеш-таблица** вместо перебора списка слоёв на каждую сущность
  (O(L) → O(1); на 300 слоях и 820 тыс. объектов это заметно).
- Счётчик «по типам» больше не создаёт `String` на каждую сущность (был миллион malloc на миллионе
  сущностей).
- При открытии большого чертежа шаг прореживания выбирается **сразу по размеру** (800 тыс. отрезков →
  шаг 8), поэтому первое открытие не даёт тяжёлого кадра.

## 1.0.3 — 2026-11-19

### Исправлено: MTEXT и кириллица

- **Фрагменты MTEXT (код 3) складывались в буфер имени слоя** — текст терялся, а «слой» превращался
  в абзац. Теперь фрагменты 3 + основной 1 собираются в один текст, а слой читается отдельно.
- **Кириллица всегда декодировалась как CP1251.** С DXF 2007 (`AC1021` и новее) файлы пишутся в
  **UTF-8**, поэтому русский текст превращался в кашу. Теперь кодировка определяется по `$ACADVER`
  плюс проверка на валидный UTF-8; старые файлы (R12/R2000) по-прежнему CP1251.
- **`trim` срезал пробелы по краям текста** — фрагменты слипались («текстапродолжение»). Значения
  текста больше не обрезаются, снимается только `\r`.
- **Имена блоков** в UTF-8-файлах декодировались как CP1251, из-за чего `INSERT` не находил блок.
  Теперь имя блока читается в кодировке файла.

### Быстрее: больше не «зависает» на больших чертежах

- Отсечение отрезков по области канвы (Коэн–Сазерленд) — в цикле растеризации нет проверок границ.
- Прореживание геометрии на дальнем плане с адаптацией по времени кадра (держит кадр в пределах
  ~30 мс) — шаг виден в статусе.
- **Бюджет надписей**: за кадр рисуется до 1200 глифов, остальные — засечками (LOD).
- **Hit-тест мыши без GDI**: ширина текста считается арифметикой, а не `measure()` на каждую надпись.
- Замер: чертёж 150 000 отрезков — было **109 мс/кадр**, стало **20 мс**; 20 000 надписей — 1.1 мс.
- Новая команда для проверки числами: `dxfsign.exe frame-bench <файл>`.

## 1.0.2 — 2026-11-19

### Исправлено: «не читается» при открытии файла

- **Путь из системного диалога приходил в CP1251 и декодировался как UTF-8.** Любое русское имя
  файла или папки превращалось в мусор, файл «не находился», и человек видел «не читается».
  Теперь пути из `GetOpenFileNameA` / `SHBrowseForFolderA` / перетаскивания конвертируются
  CP1251 → UTF-8; начальный каталог, наоборот, отдаётся в CP1251.
- **Отказ теперь называет причину**, а не «не читается»: файла нет / пустой (0 байт) /
  `AutoCAD Binary DXF` / это `DWG` (нужен Save As → DXF) / не разобран как DXF (с началом файла) /
  разобрано, но модель пуста (с разбором по причинам).
- **Файл можно перетащить в окно** (`WM_DROPFILES`): файл открывается, папка добавляется в каталог.
- **`dxfsign.exe <файл.dxf>`** сразу открывает окно (двойной клик по файлу, ассоциация, ярлык).
- **`report` больше не падает** на битом файле: печатает размер, первые байты, версию, секции,
  блоки/вставки, счётчики по типам и почему модель пуста.

## 1.0.1 — 2026-11-19

### Исправлено: не читались реальные DXF из AutoCAD

Причина была не одна, поэтому исправлений несколько:

- **Геометрия в блоках.** В реальных чертежах примитивы лежат в `BLOCKS`, а в `ENTITIES` —
  только `INSERT`. Разбор `BLOCKS` не было вовсе, и чертёж выглядел пустым. Теперь блоки
  разбираются, а `INSERT` разворачивается в геометрию с масштабом (41/42/43), поворотом (50) и
  сдвигом (10/20); сущности блока на слое «0» наследуют слой вставки, как в AutoCAD.
- **Старые полилинии `POLYLINE`+`VERTEX`+`SEQEND`** (формат R12, до сих пор встречается в цеховых
  файлах) не разбирались. Добавлены.
- **`SPLINE`**, **`SOLID`/`TRACE`/`3DFACE`**, **`ARC`** — добавлены (сплайн по контрольным точкам,
  дуга показывается окружностью — упрощение названо в спеке).
- **Последняя сущность перед `ENDSEC` терялась** — служебная запись обрабатывалась раньше, чем
  «дописать предыдущую сущность».
- **Масштабы вставки читались не из тех group-code**: 41/42/43 (X/Y/Z), а не 41/43.
- **Текст MTEXT** показывался кодом: теперь вычищаются `\P`, `\f…;`, `\H…;`, `\A…;`, `\C…;`,
  `\U+XXXX`, а `%%d` / `%%c` / `%%p` превращаются в `°`, `Ø`, `±`.
- **Неподдержанное больше не молчит**: `HATCH`, `DIMENSION`, `LEADER`, `XREF` считаются по именам
  и видны в новой команде `dxfsign report <файл>`.

```bat
dxfsign.exe report plan.dxf
:: секции, блоки, вставки, счётчики по типам сущностей и что реально попало в модель
```

Если файл и после этого пустой, `report` прямо называет причину: геометрия без `INSERT`, бинарный
DXF (`AutoCAD Binary DXF`) или только неподдержанные типы.

### Тесты

55 тестов (было 52): добавлены проверки блоков/вставок с поворотом и масштабом, старой полилинии,
сплайна, чистки MTEXT и наследования слоя «0».

## 1.0.0 — 2026-11-19

Первый рабочий релиз: утилита просмотра и правки DXF на сетевом диске с подписанным сохранением.

### Возможности

- **Правка текста надписи** (`TEXT`/`MTEXT`) мышью и с клавиатуры; список надписей чертежа в левой панели.
- После правки **обязательный номер провода** — без него правка не применяется; номер пишется в
  XData сущности (`1001 DXFSIGN`) и в письмо.
- **Свободный комментарий** к правке — уходит в перечень предлагаемых изменений, в `.txt` и в `.eml`.
- **Сохранение по протоколу версий**: прежний файл → `_VERSIONS/<имя>__<YYYYMMDD-HHMMSS>_<seq>.dxf`,
  рабочий файл перезаписывается атомарно, рядом `.txt` с перечнем, в спул `.eml` с тремя вложениями
  (новый `.dxf`, прежний `.dxf`, `.txt`), HMAC-SHA256 по канонической строке, якорь в
  `_VERSIONS/index.tsv`.
- **Каталог сетевого диска** в INI + редактор каталога в окне (`F4`), выбор папки системным диалогом,
  открытие файла `Ctrl+O`.
- **Окно Win32** без фреймворков: тулбар, наведение и подсветка, зум колесом **под курсором**,
  панорама средней/правой кнопкой, прокрутка списка, справка `F1`.
- **DXF**: `LINE`, `CIRCLE`, `LWPOLYLINE`, `TEXT`, `MTEXT`; кодировка CP1251 по `$DWGCODEPAGE`;
  round-trip с сохранением текста; неподдержанные сущности считаются и видны в `inspect`.
- **Производительность**: кадр без единой аллокации (проверяется тестом), AVX2-проекция с
  рантайм-детектом и скалярным базовым путём (×15 на 42 500 точках).

### Сборки

- `dxfsign-1.0.0-win64.exe` — Windows 10/11, rustc stable, `x86_64-pc-windows-gnu`.
- `dxfsign-1.0.0-win7-x64.exe` — Windows 7 SP1, rustc 1.77.2 (последний, у которого std работает на
  Win7). Требует KB2999226 (Universal C Runtime); импортов Win10-only нет.

Оба файла самодостаточны: без .NET, без VC++ redist, без DLL рядом.

### Проверено

- `cargo test` — 52 теста: SIMD против скаляра, DXF round-trip, CP1251, правка без номера провода,
  комментарии, RFC 4231/4648/2047, кадр без аллокаций, геометрия кликов модалки, сквозное сохранение
  с ротацией версий и разбор `.eml` независимым парсером Python.
- Окно: `--selftest` → код возврата 0 на обеих сборках.
- `.eml` разбирается `email` из Python: 3 вложения, RFC 2047-тема декодируется, SHA-256 вложений
  совпадают с заголовками и с файлами на диске.

### Что пока не входит

Реальные блоки `INSERT`/`DIMENSION` (такие файлы предохранителем не перезаписываются), отправка по
SMTP (письмо кладётся в спул), работа на настоящей SMB-шаре не тестировалась, IME и буфер обмена в
полях ввода, DPI-пересчёт метрик под 4K.
